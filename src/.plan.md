# Obsidian 语法解析器实现计划

## 项目背景

在 `smart-linter` 插件中，已有基于 remark 的 Markdown AST 解析器。但 Obsidian 在标准 Markdown 基础上扩展了多种特有语法，需要一个专门的解析器来处理这些语法元素。

## Obsidian 特有语法

需要解析的 Obsidian 特有语法包括：

| 语法类型        | 示例                | 说明       |
| ----------- | ----------------- | -------- |
| Wiki链接      | `[[文件名]]`         | 内部链接     |
| Wiki链接带别名   | `[[文件名\|显示文本]]`   | 带显示文本的链接 |
| 嵌入链接        | `![[图片.png]]`     | 嵌入图片/文件  |
| 块引用         | `[[文件#^blockid]]` | 引用特定块    |
| 标题引用        | `[[文件#标题]]`       | 引用特定标题   |
| 标签          | `#tag` `#嵌套/标签`   | 标签系统     |
| Callout     | `> [!note] 标题`    | 提示框      |
| Frontmatter | YAML 头部           | 元数据区域    |

## 实现步骤

### 第一步：创建类型定义 (`types.ts`)

定义所有 AST 节点类型：

```typescript
// 基础节点接口
interface BaseNode {
  type: string;
  position?: Position;
}

// Wiki链接节点
interface WikiLinkNode extends BaseNode {
  type: 'wikiLink';
  value: string;           // 文件名/路径
  alias?: string;          // 显示文本
  heading?: string;        // 标题引用
  blockId?: string;        // 块ID
  embed: boolean;          // 是否为嵌入
}

// 标签节点
interface TagNode extends BaseNode {
  type: 'tag';
  value: string;           // 标签值 (不含#)
  fullPath: string;        // 完整路径
}

// Callout节点
interface CalloutNode extends BaseNode {
  type: 'callout';
  calloutType: string;     // note, tip, warning 等
  title?: string;
  children: Node[];
}

// Frontmatter节点
interface FrontmatterNode extends BaseNode {
  type: 'frontmatter';
  value: string;           // 原始YAML文本
  data: Record<string, any>; // 解析后的数据
}
```

### 第二步：创建工具函数 (`utils/`)

* `position.ts`: 计算行列位置的工具函数

* `regex.ts`: 预定义的正则表达式模式

### 第三步：实现分词器 (`tokenizers/`)

每个分词器负责识别特定语法并生成 token：

1. **WikiLinkTokenizer**: 识别 `[[...]]` 和 `![[...]]`
2. **TagTokenizer**: 识别 `#tag` 格式
3. **CalloutTokenizer**: 识别 `> [!type]` 格式

### 第四步：实现主解析器 (`ObsidianParser.ts`)

核心解析流程：

```
原始文本 → 预处理 → 分词 → 构建AST → 后处理 → 最终AST
```

主要方法：

* `parse(text: string)`: 解析文本为 AST

* `stringify(ast: Node)`: 将 AST 序列化为文本

* `visit(ast, visitor)`: 遍历 AST

* `findNodesByType(ast, type)`: 按类型查找节点

### 第五步：实现转换器 (`transformers/`)

提供 AST 转换能力：

* 节点增删改

* 批量操作

* 安全修改（保持位置信息）

### 第六步：创建导出入口 (`index.ts`)

统一导出所有公共 API。

## API 设计

```typescript
import { ObsidianParser } from './parser';

const parser = new ObsidianParser();

// 解析
const ast = parser.parse(markdownText);

// 遍历
parser.visit(ast, (node) => {
  if (node.type === 'wikiLink') {
    console.log('Found link:', node.value);
  }
});

// 查找
const tags = parser.findNodesByType(ast, 'tag');
const links = parser.findNodesByType(ast, 'wikiLink');

// 修改
parser.transform(ast, {
  visitWikiLink(node) {
    node.value = node.value.toLowerCase();
  }
});

// 序列化
const newText = parser.stringify(ast);
```

## 技术要点

1. **位置信息**: 所有节点记录精确的行列位置，便于定位和修改
2. **不可变操作**: AST 修改返回新节点，保持原节点不变
3. **增量解析**: 支持只解析变更部分（可选优化）
4. **错误恢复**: 遇到无效语法时优雅降级，不中断解析
